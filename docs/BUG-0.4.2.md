# 0.4.2 缺陷分析与验证边界

## BUG-01 按压/展开闪烁
- 严重程度：S2；状态：已修复待实机验证；发现方式：用户实机反馈。
- 复现：按压入口并打开暂存栏，出现短暂闪烁；本轮未操作手机，不伪称已复现。
- 根因分析（Inference，E2 代码）：旧 StashController.show 在 addView 后 post 才设置入场 translationX，存在先显示最终位置再跳回起点的首帧窗口；每分钟 expire 即使未删除内容也重建窗口；finishCapture 的额外缩放与原卡片 Folme 按压动画竞争；原识别销毁回调可能补建收起态。
- 修复：在首次 preDraw 内设置动画初值及玻璃；保留旧表面到新表面首帧提交；内容键去重；只有实际过期才更新；保存时不再额外缩放；主动打开时短暂抑制旧识别回调。
- 五面影响：功能涉及入口/展开/过期刷新；不改变正文与图片数据；影响所有基础暂存使用者；无新增越权或数据读取；修复影响窗口生命周期/动画，须检查锁屏、连点和拖放完成恢复。
- 回归建议：TC-F01 连续打开/保存各10次并录屏观察首帧；TC-F02 无过期内容等待两分钟不应重新滑入；TC-F03 锁屏不残留任何退休窗口；TC-F04 内容拖放完成后恢复正常窗口尺寸。

## BUG-02 玻璃未生效且缺少诊断
- 严重程度：S1（可选功能降级）；状态：已修复待实机验证；发现方式：用户反馈。
- 根因分析（Inference，E2）：旧浮窗未显式声明硬件加速、未设置可用的 setMiGlassClip；返回值未检查；接口调用不等于合成器输出可见玻璃。系统 Hook 仅等待 Application.attach，晚到的插件事件可能错过初始化；没有用户可见装载/命中记录。
- 修复：硬件窗口、测量后设置裁切/双模糊，检查 Boolean false、降低盖底，失败恢复原背景；兼容已存在 Application 的初始化；精确观察 setMiGlassCompat，新增受限状态通道。保留 Disabled，不强制设备支持。
- 五面影响：功能限暂存浮窗和可选组件材质；不读写识别正文；影响开启玻璃的用户；状态写入校验 UID 包名和状态 key，系统组件仍不能访问缓存；回退、版本不符、ClassLoader 超时均需回归。
- 回归建议：TC-G01 关闭开关保持原背景；TC-G02 打开后检查诊断并观察有纹理背景下玻璃；TC-G03 框架仅勾选传送门时系统 Hook 不应显示已命中；TC-G04 添加额外作用域并重新加载后观察组件调用；TC-G05 接口缺失/返回false应回退；TC-G06 Disabled 不应被覆盖。

## 新功能：整栏拖动与半图标藏边
- 标题拖动整栏；收起入口亦可拖动；内容手势仍用于长按拖出/上滑移除。
- 靠左右边缘20dp范围松手或点收起，变成28dp宽的半图标窗口；不是在屏外放置一个大而透明的触摸层。
- 点击半图标或向屏幕内拖36dp展开；位置与藏边状态持久化；边界夹紧在纯 JVM 检查覆盖。
- TC-W01 标题拖动到中部后位置保持；TC-W02 左右藏边、点击还原、内拖还原；TC-W03 半图标旁应用可正常点按；TC-W04 重启恢复/锁屏/旋转边界；TC-W05 图片长按不误触整栏移动。

## HyperLight 只读分析结论
- 已复用现存官方1.2.2(API102) APK 解包文件，无需重复下载。
- r71.java:903–905：系统插件路径 Hook miui.systemui.util.MiBackgroundStyle.setMiGlassCompat(View,float[])。
- a81.java:576–597：统一柔光开关下替换非零42浮点材质参数（部分 JADX 循环有异常，不据此复制实现）。
- z71.java:109–114 与 r71.java:625–631：另有原生 material/clip/glass 调用。
- ji0.java:277–279、1246–1248 与 qi0.java:511–546：还存在自制 RuntimeShader 和屏幕捕获路径。因而不能把它所有“液态玻璃”都说成一个官方 Hook。
- 本版仅采用确认的原生 API 签名与目标方法进行独立实现/观察；不打包 HyperLight 反编译代码，不复制其自制渲染器，不启用屏幕捕获。
